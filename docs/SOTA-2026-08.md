## 1. Engine laws — llama.cpp × Qwen (verified against sources, as of 2026-08)

### 1.1 Slot save/restore (the core of "context as a file") — WORKS, with sharp edges

- `POST /slots/{id}?action=save|restore|erase` + `--slot-save-path DIR`. Returns
  `n_saved/n_written/save_ms`. Since PR #8699 sequence state files include **recurrent
  state** — so the Qwen3-Next hybrid (DeltaNet + attention every 4th layer)
  IS supported in explicit save/restore. 30B (classic MoE transformer) — no caveats.
- **BUT**: (a) ~~automatic context checkpoints are broken for hybrids
  (#22384, #19794, #24055)~~ **REVOKED 06.08 by measurement E17** (the reports
  predated fix PR #19408; our hazard test on b10155: reuse of 6897/7413
  prefix tokens on the second call, explicit save/restore intact
  7473/7473, output correct — `--ctx-checkpoints 8 --checkpoint-min-step
  512` IMPLEMENTED on the analyst, docs/bench/e17-ctx-checkpoints.txt);
  (b) `--cache-reuse` / context-shift **do not exist for hybrids**
  (the state cannot be reconstructed by truncation); (c) **router mode (`--models-dir`) does NOT
  proxy slot actions** (#18703); (d) a loaded mmproj (vision) blocks slot save
  (#21133). Architectural conclusion: **one plain llama-server per model,
  driven by our supervisor; we call save/restore EXPLICITLY ourselves.**
- **State contract**: the blob has NO validation metadata. Restore requires the
  same GGUF, `n_ctx` ≥ the source's, the same `type_k/type_v` and the same FA setting —
  otherwise a crash or silent garbage. That is why we version the state directory:
  `contexts/kv/<model_key>/<hash(gguf,ctx,ctk,ctv,fa,build)>/<ctx_id>.bin`.
- Numbers (proxy from the Qwen3.6-27B hybrid): ~55 KB/token of state, save ~211 ms, restore
  ~87 ms, resume **7× faster** than re-prefill. Qwen3-Next has KV on only 12/48
  layers + a fixed-size DeltaNet state — the files grow slowly. The state survives a server
  restart (files on disk), but this has to be confirmed with a smoke test on our side.
- `/slots` (monitoring) **leaks prompts** — it is enabled by default. Bind only to
  127.0.0.1 (already the case); in the packaged version additionally token + Host check.

**Wave 5 laws (hunt 05/06.08, implemented 40807b1/9cb2819):**
- **`--cache-ram 0` on BOTH models** — the b10155 default is 8 GiB of serialisation of
  idle slots into host RAM; for hybrids the path is explicitly untested
  (PR #16391 TODO). State moves ONLY through explicit save/restore.
- **`--no-kv-unified` explicitly + `-np` always pinned** — auto `-np -1` silently
  enables unified KV (leak class #25992).
- **ctx ceiling 65536 for Qwen3-Next** (`ctx_ceiling` + assertion `ctx_law()`):
  g_cum overflow in DeltaNet drives the hybrid into repetitions above ~80k
  (discussion #20000, no upstream fix).
- **Build floor b10152** — below it Qwen3-Next computes incorrectly (key_gdiff
  vectorisation fix + fused GDN #26177). Our b10155 ✓; check every rollback
  of the binary against this floor.
- **GBNF wall ≤2000** — bounded repetition / maxLength >2000 = "failed to
  parse grammar" until #26613 (b10289+). Schema audit clean.
- **Residency E9**: `residency_mode()` — dual (both servers, zero swap) when
  Σgguf×1.1+16 GB < RAM; dev 190 GB → dual, a 64 GB office machine → single from the
  same config. Shipping quant for 80B = **bartowski imatrix IQ4_NL** (E6c:
  PP +38.6% at flat TG vs IQ4_XS; sha in the model-pack manifest).

### 1.2 CPU performance (AMD, no GPU)

- **Physical cores only**: on the same architecture 80B-A3B with SMT ON drops
  from 7.74 to 2.84 tok/s (#19480). Our machine: 16 physical / 32 logical —
  `cpu_count()-2 = 30` threads is self-sabotage. Realistic 80B budget on a desktop
  AMD: **~8–12 tok/s TG**; prompt processing in the tens of tok/s — which is why
  slot-restore and fresh short contexts are the core, not a luxury.
- MoE on CPU in llama.cpp does not fully exploit sparse activation (ik_llama.cpp
  ~1.9× faster on CPU-MoE — a fallback option, not the default).
- **Speculative decoding: SKIPPED** — on A3B measured net-zero even on GPU
  (the per-token cost is already small; the draft steals the same cores).
- PP throughput: try `-b 2048 -ub 1024` (to be measured on our side).
- `--load-mode mlock` for the resident model (the office machine's 48 GB budget); with 64 GB
  total the page cache will NOT hold both models — swap = full reload from NVMe.
  Queue per MODEL (already a law) + batching phases per model minimises swaps.
- Quants: the loudly reported IQ4_XS corruption is a **Vulkan-only** bug — on CPU our file is
  correct. But i-quants have costlier decoding on CPU; K-quants (Q4_K_M / UD-Q4_K_XL
  Unsloth) have better PP. On the next download: consider replacing the 80B
  with UD-Q4_K_XL, provided it fits in 48 GB (42 GB IQ4_XS vs ~45 GB Q4_K_XL — a
  tight fit; decision after measuring the RAM peak with KV).
- KV quantisation: `-ctk q8_0 -ctv q8_0` applies only to the attention layers (on 80B:
  12/48) and is nearly lossless on hybrids; the DeltaNet state is never
  quantised. V-quant requires FA — enable through config, after a smoke test.

### 1.4 Structured output + API

- `response_format` with JSON-schema → GBNF: **guaranteed parseable JSON**,
  an overhead of a few percent. We enable it for ALL agents (slice 1). Cognitive
  caveat: the grammar enforces SYNTAX, not truth — the null-instead-of-guessing discipline

### 1.5 Qwen3 prompting laws (research 2026-08-05, second wave — IMPLEMENTED)

md-vs-XML verdict: **our markdown manuals with CAPS sections are exactly
Alibaba's official pattern** (the Model Studio guide: `#Sekcja#` headings +
sparse delimiters `===`/`>>>` around reference content). XML is neither recommended
nor penalised (the training format is ChatML + JSON-in-XML for tool calls); markdown
is ~15% cheaper in tokens. We stay with markdown; the document enters within ONE
pair of delimiters `===DOKUMENT===`.

Implemented laws (each with its source in the fork's report):
1. Task at the end (our own measurement) + **sandwich** of the key law (IFScale:
   early instructions weigh more, instruction density degrades adherence —
   limit ~20-30 rules per manual).
2. **An example of a filled-in JSON in the prompt DESPITE the grammar** — dottxt measured
   that schema-in-prompt improves field VALUES, not only the syntax; the example
   values are explicitly marked as placeholders (protection against leakage).
3. Prohibitions phrased in positive form („Przepisujesz znak po znaku" — "You copy character by character" — before „NIE
   zaokrąglasz" — "You do NOT round") — negation benchmarks.
4. Abstention: nullable schema + an explicit "null is better than a guess".
5. **presence_penalty = 0 everywhere** — the card warns about language mixing;
   for Polish reports the risk is real. Loops are caught by code (G8), not by a penalty.
6. NO "think step by step" under a grammar (llama.cpp #20345: grammar ×
   thinking clash); any reasoning = a leading `uzasadnienie` field
   in the schema (the classifier already has one).
7. Simple schemas for GBNF: no anyOf/maxLength≥2000 (known GBNF crashes);
   our type-arrays `["string","null"]` work on b10155 (smoke-verified).
8. Meta level: proposals to change prompts (from the model or from a human) are NEVER
   accepted on trust — the gate is a golden-set run (GEPA pattern:
   a stronger model as the reflector, acceptance only on a measured gain;
   self-refine without a metric = bias amplification).
9. Prompt language: the literature says "English instructions ≥ native", but there is no
   Qwen3-Polish measurement; our Polish manuals pass golden — a change only
   after a measured gain (experiment queued).

Deployment measurement: full cycle after the changes — 9/9 to the cm, zero leakage of example
values, verdict OK/high/0 problems, 113 s. Detected and fixed
along the way: a **polarity bug**: `duplikaty_id` was the only key where
false=good — the judge reported it as a problem; now in checks **true is
ALWAYS good** (`brak_duplikatow_id`) and the judge's law forbids reporting
passed checks.

## 2. Context architecture — target design

```
contexts/<ctx-id>/transcript.jsonl      # TRUTH (append-only)  [exists]
contexts/<ctx-id>/meta.json             # model, params, parent [exists]
contexts/kv/<model>/<contract-hash>/<ctx-id>.bin   # CACHE (slot save) [slice 3]
```

- **Resume ladder**: `state.bin` (restore, ~s) → absent/miss → re-prefill from the
  transcript (truth). Fork STILL copies only text — this is correct and stays.
- **Main chat (80B)**: persistent context + **rolling summary anchor** (a
  `summary.md` file updated every N turns) — resume after a restart = summary + the last
  turns, not the whole history; at 8–12 tok/s that is a difference of minutes. Exactly the
  "plan-file + re-anchor" pattern from our own workshop, carried over into the product.
- **80B vs 30B policy** (today: everything on 30B): 30B = classifier, extractors,
  judge on green checks (fast, zero swaps). **80B steps in when**:
  checks FAIL/gate conflict (arbitration), "hard" pages (low OCR confidence),
  main chat/human questions, weekly quality audit. The per-MODEL queue gathers
  80B tasks into batches — one swap, many verdicts.
- **Sticky slot per agent type**: route requests from the same agent into the same
  slot (`-sps` slot-prompt-similarity is already in the binary) — the system prompt
  (the agent's manual) gets a prefix hit without any extra machinery.
- **Token budget enforced in code**: before sending, `/tokenize` on the payload;
  the law `max_input + max_output < 0.75·ctx` moves from convention to assertion.

### 2b. Context engineering v2 — counter, AutoCompact, handoff (wave 3, 2026-08-05)

**Token counter + the 0.75 law as an assertion (IMPLEMENTED).** Every agent call
counts its input with the REAL tokenizer (`/tokenize`), and `call_agent` refuses to work
when `input + planowany_output > 0.75·ctx` — with a "re-chunk" message, before
attention degradation even begins (rot starts long before the hard
limit; our aggregations were already failing at 8–16k). `tokens_in` lands in the `_meta`
of every result — context-fill telemetry comes for free. A retry after truncation
never exceeds the window (capped at 0.75).

**Where rot CANNOT occur by construction.** The extraction crew works in
fresh contexts per call + the budget assertion → in the pipeline there is nothing
to compact. The only long-lived context = the future main chat (80B).

**AutoCompact for the main chat (design; lands with slice 5):**
1. Counter: `usage.prompt_tokens` from every server response = the current
   fill (zero extra calls).
2. Threshold: **60% ctx** → compaction (a margin before the measured onset of degradation).
3. The compactor reads **transcript.jsonl (the truth), not the live window** — a fresh
   context, structured output: decision log, open tasks, POINTERS to
   artifacts (job/extracted paths). **Numbers never flow through the
   summary** — the same law as in the pipeline: the summary carries "coordinate list: 9 pts,
   jobs/X/extracted/wykaz.json", never coordinates.
4. New window = system + `summary.md` + the last K turns verbatim. `summary.md`
   is a file editable by the operator (memory repairable by hand).
5. **Slot save before compaction → compaction is REVERSIBLE** (restoring state.bin
   brings back the full pre-compaction window) — a unique advantage of KV-as-a-file.
6. The same model compacts (80B; zero swap, no cross-model losses).

**Handoff between agents — the BLINDNESS LAW (IMPLEMENTED, revised after measurements).**
Anchoring research is clear: the phrase "verify it yourself" recovers ≤10% of the bias,
and error cascades in agent chains amplify 6–10×. That is why the handoff
is **routing, not value-carrying**: the classifier NARROWS THE INPUT (page
candidates → which pages the extractor reads), but its VALUE GUESSES never
reach the generative extractor of those fields (handing cel_pracy to the agent
that extracts cel_pracy = a textbook anchor). Values may be given
only to the judge (it generates nothing, and reads everything anyway). Technically:
a typed JSON→template built in CODE, never prose relay. Cache principle:
per-call dynamics in the USER payload (STATIC manual → prefix hit); per-job
knowledge (the county profile) in the manual's {{SLOT}} — the cache misses once per job.

**Engine cache exploitation (wave 3, source-verified):**
- 30B (standard): `--cache-reuse 256` (KV shift for repeated middle
  fragments; <2.5% quality delta at 95% reuse in the PromptCache literature) +
  `--cache-ram` (default 8 GiB; idle slots dumped to RAM and hot-swapped on
  prefix match — memcpy, not recompute). Hit telemetry: `timings.cache_n`
  → stored in `_meta.cache_n` of every result. For the 80B hybrid: NONE of this
  (shift impossible) — only explicit slot save.
- Slots do NOT physically share prefixes (confirmed in the paged-KV discussion
  #21961) — do not raise `--parallel` "for the cache"; watch item: paged KV
  Phase 2 (PR #22569) will add prefix sharing in the future.
- Exceeding the window with ctx-shift disabled = **HTTP 400**, not silent
  degradation — treated as a re-chunk signal (ctx-shift stays OFF
  forever: it cuts off the beginning of the document, poison for extraction).
- Default warmup stays ON (it loads ALL MoE experts — a predictable
  swap cost instead of lazy page faults on the first prompt); to be measured
  once: `--load-mode` without mmap (community report: ~6.7× faster first
  response at the cost of a longer load — relevant for 42 GB swaps).
- Rejected after research: DRY/XTC (n-gram penalties break table transcription),
  control vectors and reducing `expert_used_count` (no quality curves for
  extraction — experiment tier, returns only with an evaluation harness),
  logit_bias (the grammar already takes care of it).

## 3. Quality gate ladder (G1–G10)

Overriding principle (measured, in the repo since v0): the model transcribes, CODE aggregates
and judges. Gates are code; the model never overrides a gate. Second principle
(product): **abstention > guessing** — an uncertain field = `null` + the flag
DO SPRAWDZENIA ("to check") with a link to the page; the surveyor trusts the tool because it can say "I don't know".

| Gate | What it checks | When |
|---|---|---|
| **G1 schema** | JSON-schema per agent contract — enforced at DECODE (response_format) + validation on the code side | every call |
| **G2 grounding** | every extracted value must fuzzy-match a span in the page's source text; `zrodla` verified by code (LangExtract pattern) | header + coordinate list |
| **G3 referee-parser** | on born-digital pages the regex parser v1 (already exists!) counts as an independent judge of the LLM transcription; a discrepancy = row flag | coordinate list, text pages |
| **G4 dual-OCR** | on scans: a cell is CONFIRMED only when RapidOCR and Tesseract agree; disagreement → re-pass of the crop with whitelist `0123456789.,-` → still disagreement → flag | coordinate list, raster pages |
| **G5 domain** | official dictionaries by the operat's DATE: ≤2021: ZRD 1–9, **BPP 1–6**, STB 1–4, RZG 1–7; from 2021 (Dz.U. 2021 poz. 1390, the Polish Journal of Laws): **SPD/ISD** instead of ZRD/BPP, RZG disappears. Plus: first digit of Y ∈ {5,6,7,8} = zone ↔ EPSG 2176–2179; X ∈ [5.30, 6.13] million; shoelace vs declaration; count vs declaration; duplicates; date sanity (survey ≤ preparation); *TERYT* (national territorial register code) format `WWPPGG_R.OBRĘB.NR` | always |
| **G6 self-consistency** | k=2–3 samples only for pages/fields FLAGGED by G3/G4/G7; agreement per field = accepted, disagreement = null + flag | escalation |
| **G7 logprob** | min-logprob of numeric-field tokens below a threshold → row to escalation (G6/80B) | every extraction |
| **G8 generation health** | `finish_reason=length` → re-chunk/retry with a larger budget; degeneration detector (repeated rows); budget assertion 0.75·ctx | every call |
| **G9 judge digest** | the judge receives ONLY a condensed digest: FAIL checks + flags + 3 random rows with the source snippet for spot-checking. Fix for the measured over-reporting (it reported `duplikaty_id` despite `false`) | before the verdict |
| **G10 golden regression** | seeded synthetic document + anonymised real ones + **Augraphy degradations** (print/scan/fax artifacts) on rendered pages; main metric: **digit-level error rate of the X/Y columns**; no prompt/model/quant change lands without a green run | workshop pre-commit |

Rollout order: G1+G8 (slice 1, harness), G2+G3+G5 (slice 2, stages), G4+G10
(slice 4, OCR branch), G6+G7+G9 (slice 2/5).

## 4b. Document map — canonical format (research + IMPLEMENTED)

The stacks examined (Docling DoclingDocument, marker, MinerU, olmOCR Dolma-JSONL,
Azure DI markdown, Unstructured elements) converge on one pattern: **markdown
with page anchors + a JSON sidecar with offsets** — and that is exactly what we implemented:

- `jobs/<job>/document.md`: YAML front matter (doc_id, source sha256, page
  count), warnings (fragment/gaps/numbering), a table of contents with links, a section
  per page `## [s. N] <tytuł> {#pNNN}` + an invisible provenance comment
  (Azure DI pattern) + an **RFC 8118** link `operat.pdf#page=N` (the ISO
  32000-2 standard — works in Chrome/Acrobat) + content in ```text or an image for a scan.
  Citation contract for the LLM: answers cite `[s. N]`, code validates against the
  docmap (generate-then-attribute; citation-marker compliance in
  4-30B models runs at 62-88%, so validation by code is mandatory).
- `jobs/<job>/docmap.json` (sorted keys, no timestamps = diffable): pages
  {n, folio, typ tekst/tabela/skan/mieszana, nagłówek, pokrycie_obrazem,
  anchor, pdf, topics[]} (type text/table/scan/mixed, header, image coverage), toc, braki (gaps).
- **Physical-gap law** (learned on real operaty in this session):
  the folio goes through consensus (uniqueness — one public sample operat
  prints the case number on six pages; folio-vs-index offset agreement; ≥2 consistent readings), and a page
  is MISSING only when the folio jump EXCEEDS the number of PDF pages in between
  (in another one pages 4-5 are present, just unnumbered — those are not gaps; folio going backwards =
  renumbering, a note, not a gap). Three public sample PDFs (outside the repo):
  zero false alarms.
- Topics (topics[]) per page: to be added by an LLM mapper (worker, batches of ~5 pages)
  behind the same contract; the TOC is assembled by CODE (map-reduce, RAPTOR-lite pattern).
- Tables in transcripts: GFM pipe for regular ones, HTML for merged cells
  (measurement: HTML > markdown ~2pp on complex tables); images: file + caption.

### 5a. Local graph — does graph memory boost these models? (owner's question)

**YES — with three sharp qualifications, all measured.**

1. **The model NEVER queries the graph itself.** Our own benchmark campaign showed
   that off-the-shelf models are weak at a graph language without a heavy prompt ladder
   (30B: 0.246 with the full ladder vs 0.9752 for a trained 4B; anchoring by analogy
   to Cypher gave 5.5×, but that is still a league lower). Product conclusion: **code
   performs deterministic traversals, the model receives a ready digest** (300 tokens
   of the RIGHT fact instead of 8k tokens of transcript). On CPU this is a double win:
   quality (less rot in the window) and latency (PP on 80B is tens of tok/s — every
   token not read in is real seconds).
2. **The graph that pays off FIRST is the DOMAIN graph, not "LLM memory".** A boundary
   point lives for decades and appears in many operaty; parcels share
   points; the county database = the consensus geometry from the survey history. This is
   EXACTLY the bi-temporal supersession pattern (Zep/Graphiti, +15 pts LongMemEval):
   `(Punkt)-[:POMIERZONY_W {x,y,zrd,bpp,t_valid,t_invalid}]->(Operat)`,
   `(Dzialka)-[:OGRANICZONA]->(Punkt)`, a new observation does NOT delete the old one, it
   supersedes it. The product flag `nowy/zmieniony/bez_zmian` — today computed
   per operat without history — becomes literally a query against this graph
   (match by ID/position ± BPP tolerance → coordinate diff → flag + a cross-reference
   to the previous operat). The graph here is not a "prompt boost", it is the engine
   of the main function.
3. **Memory lives OUTSIDE the conversation, as an editable residue.** In-context memory
   dies with the window and rots as it fills; a file residue survives, diffs
   and can be audited. Truth = editable text (JSON/MD), indexes (graph, embeddings,
   FTS) = **a cache reproducible from the truth** — the same law as transcript vs state.bin.

**Editability by the operator — a requirement, not an option.** The surveyor signs the result
professionally, so they must see and be able to correct what the tool "believes":

- every memory entry carries **provenance and status**: `wyuczone(job-X)` /
  `potwierdzone(operator, data)` / `ręczne(operator)` (learned / confirmed / manual); manual entries win;
- **write-back at the acceptance boundary**: a human correction on the review screen
  (e.g. "in this county the columns run X Y STB RZG BPP ZRD") is saved to the county
  profile at the moment the job is approved — the moment of verification is the cheapest
  and cleanest learning signal (A-MEM pattern); code dedupes and caps;
- a **"County profile / Memory"** screen in the UI: a list of entries with provenance, editing,
  deletion, export; zero black boxes;
- hints from the profile enter the prompts as **concrete examples** (a model row
  of the table, not an abstract description) — the anchor-by-analogy law (5.5×) applies
  directly.

**Substrate in the product**: SQLite (stdlib, one file, transactions, backup = a copy of the
file) for the domain graph [nodes/edges + FTS5], JSON for the county profiles, MD for the
summary — zero new dependencies, everything offline. Neo4j remains a
WORKSHOP tool (our machine: modelling, experiments, export to SQLite), never
a dependency on the office machine. The main chat holds only the working set (rolling summary +
pointers to files) — never the knowledge base.

## 7b. Core doctrine (owner's distillate 06.08 21:36 + evidence from the arc)

Six laws through which a small model (30B/A3B) does the work of a large one — each
with a measurement in this repo; a second vertical inherits the LAWS, not the folklore:

1. **Prompts are contracts, not text.** Immutable golden + operator
   overlay; the prompt hash in the seal of every run; sampling
   profile per role (transcribe=greedy, judge=Qwen card). Evidence:
   reflection/hot-reload works without losing auditability.
2. **Decomposition into stages with an output schema.** Each stage = a short
   task + GBNF; no "read the operat and do everything". Evidence:
   the arsenal passes on 30B with the same verdicts as on 80B (wave 13).
3. **Short windows are ACCURACY, not economy.** ctx 16384; a fresh
   stateless call per image/task; digest + fragments selected
   by CODE (review); the 0.75 ctx budget as an assertion (llm.budget_check).
   Context rot is measured in the literature (Chroma 2025: degradation with
   every increase in length) — fragment routing exists for that reason.
4. **Code gates between stages.** Short windows are safe only
   when a stage's output is validated before it becomes the input
   of the next one — otherwise decomposition propagates the error instead of catching it.
   Evidence: G1–G13 + dedup_punkty (massive: blind PASS → KRYTYCZNE ("critical")).
5. **Code computes, the model reads.** All derived values (sums, deltas, shares,
   areas) are computed by code and given in the results; the narrative may quote, never
   compute. Evidence: the data-mining probe (wave 16) — the only 30B error was a sum
   computed in the narrative; the grounding gate caught it.
6. **Cheap contextual multitasking on ONE model.** KV slot save/restore
   (freezing the main thread while an agent works), a stable prefix
   through the digest hook, the compactor; residency_mode with dedupe by file (mmap).
   Evidence: the illusion of a four-person crew in ~20 GiB RAM on 30B (wave 13/15).

Core/domain boundary (next formal step): core = llm/chat/crew/
store/gates-framework/pdfpages-facade; domain = manuals, schemas,
the check library, the arsenal. A new vertical = a directory, not a fork.
